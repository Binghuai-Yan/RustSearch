# RustSearch v0.1.6

此版本完善发布流程、README 截图和后台索引调度。索引格式与 v0.1.5 相同，升级后无需重建索引。

## 后端与性能

- 添加索引文件夹时，如果待处理任务队列已满，现在立即返回 `INDEX_BUSY`，避免请求线程被队列阻塞。未成功排入任务的文件夹登记会回滚。
- 重复添加已有索引文件夹且任务队列已满时，保留原有目录登记和索引数据。
- 空闲状态下的全目录兜底核对从每 30 秒改为每 2 分钟，减少大目录反复遍历的开销。文件系统事件仍按原有 2 秒防抖处理；监听队列溢出时仍立即安排全量核对。
- 在隔离的 1 万份中文文档样例中，Release 后端索引耗时 1.28 秒，未缓存查询耗时 1–4 ms；新增文件在 441 ms 内可搜索。这些数字是本机测试结果，不代表所有磁盘和文档类型。

## 发布与文档

- GitHub Actions 的 PR 流程只运行 README 图片检查、Rust 格式与静态检查、Rust 测试，以及 WinUI/WPF 编译；`main` 和版本标签继续生成安装 EXE 与便携 ZIP。减少 PR 上不必要的发行压缩工作。
- 构建任务只持有仓库读取权限；标签发布由单独任务下载已验证的构建产物，并使用写入权限创建 Release。
- 版本标签必须提供 `docs/releases/v<版本>.md` 的详细更新记录；缺少文件或内容过短时工作流会失败，不再只显示自动生成的提交对比链接。
- README 截图重新由真实 WinUI 程序与隔离示例文档生成，缩短测试路径、替换重复的文件名并裁去设置页多余空白；每张图提供可单独打开的 GitHub 文件页链接。CI 校验图片存在、PNG 解码和尺寸。
- 已为 v0.1.5 的 GitHub Release 补写详细更新记录。

## 验证与已知限制

- Rust 31 项单元测试、2 项 PDF 子进程测试、`clippy -D warnings`、WinUI/WPF Release 编译及后端完整集成测试通过。增删改、重命名和被占用文件恢复仍在 5 秒期限内通过。
- 1 万文档监听测试通过；WinUI 浅深色、五个设置页及紧凑窗口视觉测试通过。
- GitHub Actions 无法运行需要交互桌面的 UI 自动化；正式发布包仍在本机执行桌面和安装卸载验收。
- WinUI 上微信输入法候选窗的兼容限制仍存在，随包提供 WPF 兼容界面。
