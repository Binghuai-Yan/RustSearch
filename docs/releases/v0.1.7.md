# RustSearch v0.1.7

此版本新增完全离线的图片与扫描 PDF 文字识别。OCR 默认关闭；现有纯文本、Office、EPUB 和 PDF 文本层搜索仍按原方式工作。升级会自动创建 OCR 元数据表，现有索引不需要手动重建。

## 新增功能

- 在 WinUI 与 WPF 的“索引选项”中启用 OCR，并分别选择图片、PDF 以及单个 PDF 的识别页数上限。设置页显示待识别和失败数量，可重新安排失败文件。
- 支持 PNG、JPEG、BMP、TIFF 图片中的简体中文和英文文字。扫描 PDF、混合 PDF 中缺少足够文本层的页面也可识别；原有 PDF 文本层保留，识别内容按页加入搜索索引。
- 图片可在右侧预览，OCR 文字可搜索和高亮；PDF 命中可显示识别页码。先建立索引再打开 OCR 时，已有扫描 PDF 也会自动排队。
- 普通文件索引先完成，OCR 在独立后台工作线程中逐个运行。新识别内容不会主动替换用户当前正在查看的搜索结果；手动刷新或再次搜索后显示新命中。

## 离线运行时与发行

- 便携 ZIP 和安装 EXE 都内置 Tesseract 5.5.3、简体中文与英文模型，以及 PDFium。运行时只在 `Backend/OCR` 保留一份，WinUI 与 WPF 兼容界面共用，不需要用户另装 OCR 软件或联网。
- 构建脚本固定下载版本并验证 SHA-256；首次在新构建机准备依赖需要网络和 7-Zip。第三方许可文件随包提供，完整依赖清单已更新。
- OCR 子进程与主搜索进程隔离；每页识别有超时，暂停、退出、关闭 OCR 或变更识别范围时会终止正在运行的子进程。写回前复核当前 OCR 设置、文件大小和修改时间，避免旧识别结果覆盖后来修改的文件。识别失败不会中断其他文件的索引。

## 使用方式

1. 在设置的“索引选项”开启“识别图片和扫描 PDF”，按需选择图片和 PDF，并保存。默认页数上限为 100，可设为 1 到 500。
2. 等待普通索引完成，再看设置页的 OCR 待处理和失败数量。识别结束后重新搜索关键字；失败文件可点击“重试识别失败文件”。
3. 便携版解压 ZIP 后运行 `RustSearch.WinUI.exe`；安装版运行 setup EXE。若微信输入法候选窗在 WinUI 中仍无法显示，可使用包内 `Compat/RustSearch.UI.exe`。

## 验证与限制

- Rust 单元和集成测试覆盖中文图片、扫描 PDF、启用 OCR 后补排队、搜索与预览、文件修改后旧命中清理、纯 JSON Lines 协议，以及仅启用 PDF 时大量待处理图片不会阻塞队列。
- 发布前还执行格式与 Clippy 检查、1,000 份中文文档的索引/监听回归、数据目录迁移、WinUI/WPF 桌面回归、安装版离线 OCR 和保留/删除索引两种卸载路径。GitHub Actions 运行可在非交互 Windows 环境执行的检查；桌面交互测试在本机执行。
- 单张图片或 PDF 渲染页限制为 2,500 万像素，单文件识别文本限制为 8 MiB；加密 PDF、超出所设页数的 PDF 会记录失败。图片上不绘制识别框。手写体、复杂表格没有专门模型，已有较多文本层但局部包含图片文字的 PDF 页面可能被跳过。

详细处理流程见 [OCR 设计与验收](../ocr-design.md)。
