# RustSearch v0.1.8

此版本新增标准 MCP 接口，让 Claude Desktop、Codex 等支持 stdio MCP 的客户端查询本机 RustSearch 索引。桌面程序与多个 MCP 客户端共用一个索引引擎，保留原有全文搜索与离线 OCR 功能。现有索引可以继续使用，无需重建。

## 新增：只读 MCP 工具

- `search_files`：搜索纯文本、Office、PDF、EPUB 及 OCR 内容；支持原有短语、必含/排除、文件类型、大小、日期、路径过滤，以及相关度、时间和大小排序。默认每页 20 条，最多 50 条，返回纯文本摘要和会话文档标识。
- `get_file_preview`：读取索引缓存中的正文，可定位到指定关键词附近，或按 Unicode 字符位置分段读取。默认 6000 字符，上限 20000 字符，返回 `next_offset` 用于继续读取。
- `get_document_page`：按保存的 OCR 页码读取识别文字。普通 PDF 文本层没有页码映射时返回明确错误。
- `list_index_roots` 与 `get_index_status`：查询索引目录、文档数量、OCR 队列及共享引擎状态。
- WinUI 和 WPF 的设置“关于”页增加配置复制按钮，自动生成当前安装路径对应的 Claude Desktop JSON 与 Codex TOML。WPF 兼容界面共用主目录中的 MCP 程序。

## 共享引擎与数据保护

- 桌面端和 MCP 通过本地 Windows 命名管道共用一个后端，避免多个进程同时写入 Tantivy/SQLite。请求标识独立映射，关闭一个客户端不影响其他客户端；全部断开后引擎退出。
- MCP 会话在引擎异常退出后自动重连。标准协议支持初始化协商、字符串/数字请求标识、取消请求、结构化结果和工具错误。
- MCP 查询不写入桌面搜索历史。只开放查询工具；正文预览必须使用本次会话搜索发现的文档标识，并通过后端再次检查索引目录范围。文件已修改但尚未更新索引时，不额外提取文件正文。
- 管道权限限制为当前 Windows 用户，拒绝远程管道连接。索引引擎和 OCR 保持本地运行；MCP 客户端可能将检索正文传给模型服务，取决于客户端设置。
- 数据目录迁移增加独占租约，防止复制过程中另一个客户端启动旧目录的引擎。迁移前需关闭 MCP 客户端；仍有其他连接时明确返回忙状态。迁移锁不会被复制到新目录。

## 修复与发行改进

- OCR 改用文件句柄向 Tesseract 输入图片并接收文字，模型目录使用相对路径，避免 Tesseract/Leptonica 按系统 ANSI 代码页打开中文、表情符号路径的问题。已在同一个中文及表情符号路径上复现旧调用失败、验证新调用识别成功，并加入 MCP 回归样例。
- MCP 握手报告 RustSearch 产品版本；参数上限、正文长度、无效文档标识和错误结果有真实进程回归测试。
- 紧凑设置窗口验证新增 MCP 按钮的可见性与剪贴板内容；继续覆盖主题、预览定位、托盘、重连和迁移。
- ZIP 与安装 EXE 均包含 `Backend/rustsearch-mcp.exe` 和 MCP 使用文档。GitHub Actions 在构建后测试实际打包的 MCP 程序，再上传发行文件；第三方许可清单补充官方 Rust MCP SDK、Tokio、SHA-2 和 Windows API 接口。

## 使用方式

1. 安装 EXE，或解压 ZIP 后运行 `RustSearch.WinUI.exe`；WPF 兼容入口为 `Compat/RustSearch.UI.exe`。
2. 在桌面设置添加需要检索的文件夹，等待索引完成。需要搜索图片或扫描 PDF 时启用 OCR，并等待识别完成。
3. 打开“设置 → 关于”，复制对应客户端配置，将其合并到已有 MCP 配置中，保留其他服务器条目。
4. 重启或重新连接客户端，确认能发现 `search_files` 等五个工具，随后检索本机文档。
5. 更换并迁移数据目录前关闭 MCP 客户端；重新连接后默认跟随桌面保存的新目录。使用 `--data-dir` 固定目录的配置需要手动更新。

## 验证与限制

- 本地验收包含 32 项 Rust 单元测试、3 项 MCP 真实进程测试、4 项 PDF/OCR 测试，及格式、Clippy、中文索引与文件监听、数据迁移、WinUI/WPF 窗口、安装和保留/删除数据两种卸载路径。
- MCP 测试覆盖旧版协议协商、字符串标识、双 MCP 客户端与桌面共用同一个引擎 PID、中文搜索与 OCR 页码、历史隔离、预览分段、错误参数、迁移阻止和强制终止引擎后的自动重连。
- 标准协议和官方 SDK 驱动的真实进程测试已完成；Claude Desktop、Codex 具体客户端界面未在本机逐一实测。
- 当前提供 Windows x64 stdio 接入。OCR 页码工具依赖已保存的页码映射；文档标识在会话结束或缓存清理后需要重新搜索获取。迁移测试中的符号链接场景因本机未具备创建权限跳过。
