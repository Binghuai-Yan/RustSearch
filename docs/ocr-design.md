# 离线 OCR 设计与验收

## 范围

OCR 默认关闭。开启后支持 PNG、JPEG、BMP、TIFF 图片，以及无文本层或混合内容的 PDF。文字由本地 Tesseract 5.5.3 的简体中文和英文模型识别；PDF 由本地 PDFium 渲染。原有 PDF 文本层仍由文本提取器获取，PDF OCR 逐页跳过已有足够文字的页面。识别结果进入 Tantivy 全文索引，SQLite 保存全文、页码范围、待处理及失败状态。预览显示图片和可搜索的 OCR 文字，PDF 命中可显示页码。

## 流程

1. 普通索引先遍历文件并提取现有文字。图片及需要 PDF OCR 的文件标记为待识别，不阻塞文件夹索引完成。
2. 单个后台工作线程按入库顺序读取符合当前设置的文件，在独立子进程中识别。每页 Tesseract 限时 30 秒，整个文件限时 310 秒；单个 PDF 的页数上限可设为 1 到 500，默认 100。图片和渲染页面限制为 2500 万像素，全文限制为 8 MiB。
3. 写回前检查文件大小和纳秒级修改时间，并使用索引变更锁；过时结果丢弃。成功后先提交 Tantivy，再保存 SQLite 全文和页码。进度通过 `ocr.finished`/`ocr.failed` 事件上报；当前搜索结果不会自动刷新。
4. 文件改变后，增量索引会清除旧 OCR 页码并重新排队。识别失败保留失败状态和消息，可从设置页重试。关闭 OCR 不删除已识别的搜索结果；重新启用或修改类型设置时会重新安排适用文件。

## 运行时与发行

`scripts/prepare-ocr-runtime.ps1` 将固定版本的 Tesseract、PDFium 与 `chi_sim`/`eng` 模型下载到依赖缓存，验证 SHA-256，并保存许可文件。`build.ps1` 把运行时复制到 `Backend/OCR`；WinUI 和 `Compat` WPF 后端共享这一份。ZIP 与安装包均离线可用。构建机首次准备运行时需要网络和 7-Zip，终端用户不需要另装 OCR 软件。

## 验收

`cargo test --locked` 的集成测试用中文图片和扫描 PDF 验证识别、搜索、预览页码、stdout JSON Lines，以及图片修改后的旧命中清理。`./build.ps1 -TestInstaller` 验证两个前端的实际启动、桌面回归、安装与卸载，并在无运行时环境变量时调用安装目录中的两个后端识别中文图片。OCR 测试需要先运行准备脚本并将输出目录设置为 `RUSTSEARCH_OCR_RUNTIME_DIR`。

## 当前限制

不绘制图片识别框；手写体与复杂表格没有专门模型。加密 PDF、超过页数或像素限制的文件会记录失败。PDF 采用页级跳过策略，已有文本层但其中部分字是图片的页面可能不触发 OCR。当前仅有一个 OCR 工作线程，以维持搜索响应和普通索引吞吐。
