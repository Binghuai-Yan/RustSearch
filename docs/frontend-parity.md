# 三个前端的功能同步与发布约定

WinUI、WPF、Tauri 是同一应用的不同界面。每次正式发布必须提供同版本的三套独立 ZIP 和三套安装器，不将另一个前端嵌套进包内。布局和控件可使用各框架的惯例，搜索和数据处理行为以共享后端为准。

| 功能 | 三个前端的共同要求 | 验证 |
| --- | --- | --- |
| 搜索 | 中文即时查询、语法、类型筛选、排序、每页 50 条 | 三套桌面回归、后端测试 |
| 预览和文件操作 | 高亮、安全文本、打开文件、打开目录、复制路径 | 桌面回归 |
| 历史 | 使用共享索引中的搜索历史 | 后端与桌面回归 |
| 索引管理 | 添加、移除、重建、暂停/恢复、状态进度 | 桌面与后端回归 |
| OCR | 图片、扫描 PDF、中英模型、页数限制、失败重试 | 共享资源哈希、OCR 测试 |
| 索引设置 | 文件大小、排除目录、自定义词典 | 共享 `config.get/set` |
| 外观和托盘 | 浅色/深色、关闭到托盘或退出、单实例、`--exit` | 共享偏好文件、桌面回归 |
| 数据目录 | 打开、迁移到空目录、切换已有目录、取消、失败回滚 | 共享迁移代码和专项测试 |
| MCP | 同包服务端、连接状态、Claude/Codex 配置复制 | 三包 MCP 集成测试与桌面回归 |

`frontends.json` 定义发行入口、安装 ID、功能约定版本、分页大小和文件类型筛选。三套前端在编译时直接读取同一份分页/筛选配置，包含 EPUB、文本、代码、Office 和图片，避免选项各自演变。新增功能必须同步更新三套入口与相关回归；仅修改这个文件或 `release.json` 不代表实现了功能。后端功能尽量放在共享 RPC 中，文件迁移的校验、锁、清理逻辑只维护 `RustSearch.UI/Services/DataDirectoryMigration.cs` 一份，Tauri 的迁移辅助程序链接同一源码。

三套界面共享默认数据路径和 `ui-settings.json` 指针。索引目录内的 `config.json`、搜索历史、词典、`ui-theme.txt` 与 `ui-preferences.json` 共用；窗口布局可以独立。后端变更通过同一引擎广播，后端设置在面板重新打开时读取已保存的值，主题在启动时读取共享偏好；不强制改变另一个已打开窗口的主题。迁移必须关闭其他前端和 MCP 客户端，服务端拒绝在存在其他连接时移动索引。

版本来源是根目录 `VERSION`。运行 `scripts/sync-version.ps1 -Version <版本>` 同步 Rust、Tauri、npm 及锁文件，.NET 通过 `Directory.Build.props` 读取同一值。`-Check` 只验证，不修改源码。

`build.ps1` 默认构建全部版本，共用一次 Rust 后端产物，复制相同 MCP 和 OCR 文件，生成独立安装器、ZIP 和带 SHA-256 的 `RustSearch-<版本>-release-set.json`。每个安装器独立注册、升级和卸载；默认静默卸载保留共享用户数据。显式删除共享索引会影响其他前端。

发布前执行：

```powershell
./build.ps1 -TestInstaller
./scripts/test-release-packages.ps1
```

CI 在拉取请求和标签上构建三个包、运行后端/迁移测试与三个桌面回归。无人值守环境的 WinUI 回归使用 `-SkipPointerInput`，保留键盘调整窗格测试，物理鼠标拖拽需交互桌面验收。标签发布再校验六份文件的哈希，先上传到草稿 Release，所有文件到齐后统一公开；缺少任何前端或检查失败都不会公开本次新 Release。真实第三方中文输入法候选窗仍属于物理桌面验收，composition 模拟不能替代它。
